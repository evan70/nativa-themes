Témy pre deti ... diel 1: téma ako modul

2026-10-02 · Architecture · Nativa Dev · 3 090 views

Predtým bola téma vec. Nešlo o triedu ani o súbor — šlo o to, že niekde v kóde bolo rozhodenie, niekde bol far, niekde bol padding. Rozhodenie, far a padding nemali nič spoločné okrem slova „téma".

Prvý diel tejto série je o tom, ako sa z rozliatej zmesi stane modul: jedno miesto, ktoré vieš otvoriť a prečítať.

Čo bola téma predtým

Tri príčiny, prečo sa téma rozlievala. Každá z nich vyzerala beznehučne — a práve preto fungovala dlho.

  • Farby v inline styloch, ktoré nikto nehladal.
  • Rozhodnutia o marži, ktoré žili v šablóne, nie v token-e.
  • Vetvy podmienené tým, čo je „naša" téma a čo nie.

Téma nebola vec. Bola rozliata zmes, ktorá vyzerala ako vec.

Kontrakt

Kontrakt je rozhranie. Šestnásť metód: osem pre identitu a Assety, tri pre chrome a sedem po jednej pre každú verejnú plochu. 

public function header(ShellContext $context): string;
public function footer(ShellContext $context): string;
public function pageWrap(string $content): string;
public function homepage(PageContext $context): string;
public function blogIndex(PageContext $context): string;
public function blogArticle(PageContext $context): string;

Konektor

Jeden súbor zisťuje, že téma erik je ErikTheme. Všetky ostatné súbory majú o téme žiadnu vedomosť — a architektúrny test to kontroluje.

Čo zostalo v jadre

Head konektor. Meta pre vyhľadávače, JSON-LD, nonce — to patrí jadru, nie téme. Téma začína až za <body>.
